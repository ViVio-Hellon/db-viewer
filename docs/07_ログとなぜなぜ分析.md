# ログとなぜなぜ分析

「エラーが出た」「保存できなかった」と言われたとき、**あとから何が起きたかをたどれる**ようにするための仕組みです。
画面のエラーには **記録番号**(8 桁の英数字)が出ます。その番号を 設定 →「ログ」 に入れると、
その操作の前後(どの画面で・誰が・何を押し・何が返り・その前に何があったか)が一続きで出て、
なぜなぜ分析の下書きもそこからコピーできます。

## 0. 0.11.0 で足したもの(参照: ViVio-Hellon/vba-daily-report-python-migration の「ログ」)

| 足したもの | 中身 |
|---|---|
| 呼び名 | 設定の面を「記録」→「**ログ**」に |
| **なぜなぜシート** | 記録番号の前後の窓の下で、**なぜ 1〜5・対策・対策の状況(未着手 / 対策中 / 対策済)・書いた人** を書いて残す。ログの出力先の `dbviewer\dbviewer_なぜなぜ_<PC名>.jsonl` に 1 回 1 行(書き直しても前の行は消さない。いちばん新しいものが効く) |
| 見るもの | 「**エラーだけ**」「エラー・断り・警告」「操作も全部」と、**PC** で絞る。一覧に なぜなぜ の状況(エラーで未記入なら「未着手」) |
| **CSV に書き出す** | いまの絞り込みのまま、ログの出力先の `書き出し\エラー一覧_日時.csv` へ(Shift_JIS。Excel で開ける)。例外・例外の場所(このツールのどのファイルの何行目か)・なぜ 1〜5・対策・状況・書いた人 の列も入る。ダウンロードはしない |
| 見出しの数 | この 2 日の、まだ「対策済」にしていないエラーの数を、左のレール(設定に「エラーN件」)とログのタブに出す。対策済にすれば消える |
| 出力先(掃き出し先)に戻る | 設定の出力先(共有フォルダなど)に書けないあいだは この PC の既定の場所に書き、**5 分ごとに設定の出力先を試し直す**(起動し直さなくても戻る)。一覧は両方を読む(書けなかったあいだのぶんも並ぶ) |
| コードの中の警告も拾う | `log.warning` / `log.exception` に書いたもの(握りつぶしていたエラー)もログに 1 行(「警告(コードの中)」「エラー(コードの中)」)。同じものは 1 分に 1 度、間引いた数を添える |
| 直前の操作 | 画面のエラーに、その前に押したボタン・選んだ欄の**名前** 15 件を添える(打った値は送らない) |

## 1. 何が残るか

| ファイル | 中身 | 読む人 |
|---|---|---|
| `dbviewer_記録_<PC名>_YYYYMMDD.jsonl` | **操作の記録**。1 行 = 1 つの出来事(JSON)。画面を開いた・書いた・断られた・エラー・ログイン・起動終了 | 管理者(設定「記録」で読む) |
| `dbviewer_<PC名>_YYYYMMDD.log` | 開発者向けの詳しいログ(テキスト)。思わぬエラーのトレースバックもここに | 開発者 |
| `dbviewer_取り込み診断_<PC>_YYYYMMDD.log` | Access の変換・表を持ってくる の診断 | 開発者 |

**置き場所の中に `dbviewer` フォルダを作り、その中に書きます。ファイル名もすべて `dbviewer_` で始まります**(0.33.0)。
共有フォルダを置き場所にすると rneconverter・日報などほかのツールも同じ所に書くので、フォルダを見ても、ファイルだけ取り出しても、
どのツールのものか分かるようにしています(操作の記録の 1 行にも `"app": "dbviewer"` が入ります)。

    <置き場所>\dbviewer\dbviewer_記録_<PC名>_YYYYMMDD.jsonl
    <置き場所>\dbviewer\dbviewer_<PC名>_YYYYMMDD.log
    <置き場所>\dbviewer\dbviewer_取り込み診断_<PC名>_YYYYMMDD.log
    <置き場所>\dbviewer\dbviewer_なぜなぜ_<PC名>.jsonl

0.32.0 までのファイル(置き場所の直下の `記録_…`・`なぜなぜ_…` など)はそのまま残します(消しも動かしもしません)。
この PC の既定の場所(ローカル領域)にあるものは読みますが、**共有フォルダの直下にあるものは読みません**
(ほかのツールも同じ `記録_…` の名前で書いているので、混ざるため)。

ファイル名に **PC 名** が入っています。共有フォルダに置いても、PC ごとにファイルが分かれる(同じファイルを取り合わない)ためです。
日付は書いた日で、日をまたいで開いたままの端末も翌日のファイルに書きます。

## 2. 出力先(掃き出し先)と残す日数(設定「ログ」)

| 項目 | 既定 | 説明 |
|---|---|---|
| 出力先(掃き出し先) | `%LOCALAPPDATA%\DBViewer\logs` | **共有フォルダにすると、どの PC で起きたことも 1 か所で引けます**(おすすめ)。相対パスはアプリのフォルダ基準 |
| 残す日数 | 90 | 起動したときに、**この PC の** それより古い記録だけ消す。0 = 消さない |

- 書けない場所は保存しません(理由を出します)。保存すると**その場で**新しい場所に書き始めます(起動し直さなくてよい)。
- 置き場所を変えると、**前の場所と新しい場所の両方に**「記録の置き場所を変えた」が残ります。前の記録を見ている人が続きの場所を知るためです。
- 設定の出力先に書けない(共有フォルダにつながらない等)ときは、この PC の既定の場所に書き、
  「ログ」タブに「既定の場所に書いています(5 分ごとに試し直します)」と出します。つながれば**起動し直さなくても**戻ります(0.11.0)。
- 記録はログイン無しでも見られます(ログインできないこと自体を追うため。設定画面と同じ)。
  **ログイン ID や直した値が入る**ので、共有フォルダに置くときはフォルダのアクセス権を絞ってください。
  パスワードなど名前に pass / token / secret を含む値と、起動トークン(URL の `t=`)は「***」にして残します。

## 3. 記録番号

- 画面からサーバへの要求ごとに 1 つ振ります(応答ヘッダ `X-Request-Id`)。
- 画面のエラーの知らせには「記録番号 xxxxxxxx」が出ます。
  - **断り**(Level が足りない・入力の誤り・ほかの端末と競合 など。理由は文に書いてある): 番号だけ
  - **思わぬエラー**(サーバのエラー・画面の中の JavaScript のエラー): 番号と「記録を見る」ボタン。押すと設定「記録」でその前後が開く
- 画面の中(ブラウザ)のエラーも記録に送ります(1 画面で 5 件まで。同じエラーは 1 回)。これまでは開発者ツールを開かないと何も残りませんでした。

## 4. 1 行の中身

| 項目 | 意味 |
|---|---|
| `t` | 時刻(ミリ秒まで) |
| `lv` | INFO / WARN(断り)/ ERROR(エラー) |
| `ev` | 出来事の種類(下の表) |
| `msg` | 画面に出した文言・一言 |
| `rid` | 記録番号 |
| `sid` | 画面(タブ)の番号。同じ画面の前後をたどる鍵 |
| `user` / `lvl` | ログイン ID / Level(ログイン前は無し) |
| `pc` / `ver` | PC 名 / アプリの版 |
| `method` / `path` | 操作の種類と URL(起動トークンは外す) |
| `st` / `ms` | 結果の状態(200 = 通った、4xx = 断り、5xx = エラー)/ かかった時間 |
| `data` | 中身。直したマスの前 → 後、断りの理由コード、送った値の要約など |
| `exc` | 例外の種類・文言・トレースバック(どのファイルの何行目か) |

### 出来事の種類

| `ev` | 画面の呼び名 | いつ | `data` に入るもの |
|---|---|---|---|
| `screen` | 画面を開いた | 画面を開いたとき | — |
| `request` | 操作 / 断られた / エラー | 書く操作(POST)と、断られた・エラーになった要求すべて | 送った値の要約、理由コード |
| `error.server` | 思わぬエラー(サーバ) | サーバの中で思わぬ例外 | 送った値、例外とトレースバック |
| `error.client` | 画面の中のエラー | ブラウザの中で JavaScript のエラー | 文言・スタック・場所 |
| `login.ok` / `login.ng` | ログイン / ログインできなかった | ログイン | ID・OS の ID・PC・理由 |
| `cell.save` | 一覧で直した | 一覧のマスを直して保存(断られたときも) | キー・列・前 → 後・理由 |
| `record.save` | レコードを保存 | 登録画面の 新規・修正・削除 | 変えた項目の 前 → 後 |
| `master.save` / `master.delete` | マスタを保存 / 削除 | マスタ管理 | 表・キー・前 → 後 |
| `master.add_column` | 列を追加 | マスタ管理の「＋ 列を追加」 | 表・列名・種類・入れた値・一緒に足した設定の行・控えの場所 |
| `settings.save` / `db.open` / `settings.reset_mode` | 設定を保存 など | 設定 | 送った値 |
| `accdb.convert` / `table.bring` / `table.refresh` | Access を変換 など | Access 取り込み | 元・保存先・表 |
| `export` / `print` / `report` | ファイルに保存 / 印刷 / 帳票 | 出力 | 行数・列(保存先は文言に)・帳票の対象キー |
| `job.done` / `job.failed` | 長い処理が終わった / 失敗 | 変換などの長い処理 | 結果・例外 |
| `log.moved` | 記録の置き場所を変えた | 設定「記録」 | 前の場所・新しい場所 |
| `app.start` / `app.stop` | 起動 / 終了 | 起動・「終了」・誰も見ていないので自動終了 | アプリと本体の場所・記録の場所・消した古い記録の数 |

心拍(15 秒ごとの生存確認)や、画面を開いたあとの読み込み(GET)は残しません。埋もれるためです。

## 5. なぜなぜ分析の手順

1. **記録番号を聞く。** 画面の知らせに出ています(コピーできる字で出しています)。番号が分からなければ、だいたいの時刻と画面を聞く。
2. **設定 →「ログ」→「記録番号で引く」** に入れて「前後を見る」(エラーの知らせの「記録を見る」からも同じところに来ます)。
   番号が無ければ「最近の記録」を **期間** と **言葉**(ID・画面・理由・値)で絞って探す。
3. **前後を読む。** 色の付いた行がその記録番号。上が古い。同じ画面・同じ PC の前後 15 分と、画面の無い出来事(長い処理・起動終了)が並びます。
   行を開くと、送った値・断りの理由・例外の場所が見えます。
   **ほかの PC が関わっていそうなとき**(競合など)は、「すべて」にして言葉(キーや表の名前)で絞ると、ほかの PC の同じ行への書き込みが出ます(置き場所が共有フォルダのとき)。
4. **なぜなぜシートに書いて「なぜなぜを残す」**(0.11.0)。状況を「対策中」「対策済」にすると、見出しの「エラーN件」が減る。
   「CSV に書き出す」で、なぜなぜの列も入った一覧を Excel で開ける。
   **「なぜなぜの下書きをコピー」** を押せば、メール・チャット・報告書にも貼り付けられる。
   下書きには事実(いつ・誰が・どこで・何が・状態・例外の場所・中身・その前に起きていたこと・その後)が入り、
   「なぜ1〜5」「真因」「対策」「歯止め」は空けてあります(考えるのは人)。
5. **事実から一段ずつ「なぜ」を書く。** 推測には「?」を付け、記録で確かめられたら外す。
   真因が分かったら、対策(誰が・いつまでに)と歯止め(同じことが起きないように)を書く。

### 例 1: 一覧で直したら「他の端末が先にこのマスを変えていました」

```
【起きたこと(事実)】
  いつ   : 2026-10-01T10:42:13.204
  誰が   : taro(Level 3)/ PC NLM-NGY-0101
  どこで : 一覧(その場で直す)  POST /api/list/cell
  何が   : 一覧で直した  他の端末が先にこのマスを変えていました。いまの値に置き換えたので、もう一度直してください。
  状態   : 409(かかった時間 12 ms)
  中身   : {"key": "12", "column": "作業名", "before": "旧名", "after": "新名", "reason": "conflict", "changed": []}
【その前に起きていたこと】
  10/01 10:31:02 画面を開いた [一覧]
  10/01 10:31:02 操作 [一覧] POST /api/list/data(35 ms)
【その後】
  10/01 10:42:13 断られた [一覧(その場で直す)] 状態 409 他の端末が先にこのマスを変えていました。…
```

(`before` は画面が見ていた値、`after` は入れようとした値。)
「すべて」にして `作業名` と `"12"` で絞ると、10:40 に PC NLM-NGY-0207 の hanako が同じ行を直した「一覧で直した」が出る。

- なぜ1: 保存が断られた → 画面が見ていた値(旧名)と本体の値が違ったから(reason = conflict、状態 409)
- なぜ2: 本体の値が違った → 10:40 に別の PC で同じ行が直されていた(hanako の cell.save)
- なぜ3: 2 人が同じ行を直した → ? 担当の割り振りが決まっていない
- 対策 / 歯止め: …(人が決める)

断りは**消えるはずだった変更を守った**結果です。画面は「いまの値」に描き直しているので、直し直せば保存できます。

### 例 2: 思わぬエラー(500)

知らせの「記録を見る」→ 色の付いた行を開くと `exc` に例外の種類と**どのファイルの何行目か**、`data.sent` に送った値が出ます。
下書きの「場所」の行をそのまま開発者に渡してください。同じ番号で `dbviewer_<PC>_日付.log` を探すと、前後の詳しいログも読めます
(`思わぬエラー rid=xxxxxxxx` の行)。

## 6. 見つからないとき

| 症状 | 理由 |
|---|---|
| 記録番号が見つからない | 置き場所を変える前の記録は前の場所にある / 30 日より前 / 置き場所が PC ごと(既定)で、別の PC で起きた |
| ほかの PC の記録が出ない | 置き場所がその PC の中(既定)。共有フォルダにそろえると 1 か所で引ける |
| 「既定の場所に書いています」 | 設定の場所(共有フォルダ)に書けなかった。つながってから起動し直すか、置き場所を見直す |
| 記録が増えすぎる | 残す日数を短く。消すのは起動したときで、各 PC が自分の分だけ消す |

## 7. 開発者向け

- 書く: `dbviewer/trace.py` の `trace.event(ev, msg, level=, data=, exc=, **fields)`。**例外は出さない**(書けなくても業務を止めない)。
  要求の中で呼べば `rid` / `sid` / `path` / `user` は自動で入る。`data` は `summarize()` で縮め、秘密を伏せる。
- 要求ごとの記録と 500 の受け止めは `app/__init__.py` の `_register_trace`。起動の記録・古い記録の削除は `_start_records`。
- 読む: `trace.read(days, only_problems=, q=, limit=)`、`trace.chain(rid)`。画面の呼び名・下書きは `dbviewer/presenters/log_view.py`。
- API: `POST /api/log/client`(画面のエラー)、`GET /api/log/events`、`GET /api/log/chain?rid=`、`POST /api/log/open`。
- 画面側: `app/static/js/errlog.js`(画面のエラーを送る)、`toast.js` の `toastError(err, kind)`(記録番号を添える)、
  `views/log_tab.js`(設定「記録」)。
- JSONL なので、Python なら `json.loads` を 1 行ずつ、Excel なら Power Query の JSON で読めます。
