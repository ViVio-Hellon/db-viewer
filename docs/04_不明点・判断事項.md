## 確認していただきたい判断事項

各項目に推奨案を書いています。異なる場合は番号でお知らせください。

- **D1** 配置先: **db-viewer を独立アプリ**（python-web-tools の基盤を複製）にするか、梱包資材総合ツールの中に画面として足すか。
  推奨: 独立アプリ。業務も DB も権限モデルも別で、同じ基盤を複製すれば「既存基盤の再利用」は満たせます。
- **D2** Access の読み取り手段: **cscript → VBScript → ADODB → ACE**（ご指定）で取り込みツールを作る。
  推奨: そのとおり。pyodbc は使いません。
- **D3** 日付の格納形式: SQLite の TEXT に **'YYYY/MM/DD hh:mm:ss'（VBA と同じ）** か ISO 8601 か。
  推奨: VBA と同じ形式。既存の文字列列・フィルタ・自動項目の互換が保てます。並び替えはゼロ埋めなので文字列比較で正しく効きます。
- **D4** 他システム（progNo 1〜3, 5〜7）の扱い: エンジンは汎用のまま、**帳票 3 本と CoinInputFm はプラグインとして移植するが progNo=4 以外は未検証** とするか、完全に対象外とするか。
  推奨: プラグインとして移植（コードは削らない）。検証は実データのある progNo=4 のみ。
- **D5** 文字色設定の JS 式: **ブラウザで同じ JS を評価**する（VBA も JScript 評価）か、Python で限定的な構文だけ解釈するか。
  推奨: ブラウザで評価（表示だけの規則で、設定は管理者が書く）。
- **D6** DB の持ち方: **共有 sqlite3 を直接読み書き**（VBA と同じ運用）か、手元 DB に取り込んで書き戻す python-web-tools 方式か。
  推奨: 直接読み書き（読みはスナップショット）。登録した結果が他 PC にすぐ見える VBA の使い勝手を保てます。
- **D7** ログインの有効期間: **プロセスの寿命**（VBA 同等）か、無操作 N 分で再ログインか。
  推奨: プロセスの寿命を既定に、無操作再ログインは設定で任意。
- **D8** 多重タブ: **タブを独立**させる（状態を持たない）か、python-web-tools のように最後のタブだけ操作可能にするか。
  推奨: 独立。競合は行単位の 409 で守ります。
- **D9** 帳票の出し方: **HTML 印刷（6mm 余白）+ xlsx 出力の両方**か、どちらかだけか。
  推奨: 両方。印刷は HTML、保存・再加工は xlsx。
- **D10** Python の追加パッケージ: python-web-tools と同じ **Flask + waitress の 2 つだけ**を前提としてよいか（標準ライブラリのみの制約との関係）。pip 不可 PC には wheel を同梱して `pip install --no-index` で入れる案。
  推奨: 2 つを前提。既存ツールと同じ配布手順が使えます。

## 受領済み資料と、そこから分かったこと（2026-09-30）

**受領**: `作業標準管理システム.accdb`（不明点 #1, #2, #7, #8, #9 を充足）、`出力原紙.xlsx`（不明点 #3 を充足。VBA の実出力シート 2024-03-28 / 2024-10-02 入り）。テスト基準として `tests/fixtures/realdata/` に TSV 化して保存した（PASS は伏せ字、.accdb 本体は保存しない）。

**確定した事実**

- `全般設定`: メインテーブル名=作業標準管理、初期表示=一括、初期フィルタ=空、帳票=`/出力原紙.xlsx/作業標準/REPORT`。
- `フィルタ` 11 件（作業名, 作業NO(100), 危険度分類ランク(35), 区分(80), RA, PC化, 完了, 廃止, 危険源分析, 担当, 課長承認(各40)）。`タイプ` 7 件（>=, <=, >, <, YYYY, YYYYMM, 作業NO）。

**新たに分かった不明点（要確認）**
- **#18 帳票 REPORT の列番号が現在の DB と合わない。** VBA の `sj = (1..9, 12, 20, 21, 26, 27)` は 27 列以上ある旧レイアウト前提で、出力例の見出し（9 列目=危険度分類ランク, 10=廃止, 11=文書番号, 12=更新者, 13=更新日）もその旧レイアウトに対応している。現在の DB は 25 列で、危険度分類ランク=11, 廃止=18, 文書番号=19, 更新者=21, 更新日=23。つまり **現在の DB で VBA の帳票ボタンを押すと添字エラーになる（または別の列が出る）はず**。Web 版では列を「名前」で選ぶ（出力例の見出しどおり 13 列）方針でよいか。
- **#19 列名と中身のずれ。** 現在の `更新者` 列に A/B/C（ランクらしき値）、`登録者` 列にユーザー ID、`登録日` 列に日付が 7 件だけ、`更新日`/`完了日` 列に日付、が入っている。出力例の「更新者」列の値は現在の `登録者` 列と一致する。列の付け替えが過去にあったと見える。Web 版は **列名のまま**（中身を解釈しない）で移植し、データの是正は運用側で行う、という理解でよいか。
- **#20 `pe$P2/0/500/1` の意味。** 入力形式 `$` は「専用フォーム」だが、`pe` というフォームは VBA に無い（`$` 直前の `pe` が接頭辞、`P2/0/500/1` が引数）。`TextDblClickEvents` の `$` 分岐の実装を再確認し、該当フォームが無い場合の VBA の挙動（数値 0〜500 刻み 1 の入力と推定）を出力例で確かめる。
- `RA` `PC化` `完了` 列の `?` は DB の値そのもの（出力例にも同じ `?` がある）。文字化けの名残と見えるが、Web 版はそのまま扱う。
