### 照合で分かったデータ側の事実（是正は運用側）
- 帳票の「更新者」「更新日」列は VBA 出力例と値が違う。原因は列の付け替え（#19: 現在の `登録者` 列に出力例の「更新者」の値が入っている）で、Web 版は列名のまま扱う。
- `RA` `PC化` `完了` の `?` は DB の値そのもの。
- 作業名の半角カナ/全角カナは VBA 出力例と DB で表記が違う行がある（#20 と同種）。比較は `StrConv(vbNarrow)` 相当を通して行った。

## 2. 意図した差異（VBA と違えたところ）

| # | VBA | Web 版 | 理由 |
|---|---|---|---|
| 1 | 2 台が同じ行を修正すると後勝ち（黙って上書き） | 開いたときの値と現在値を `BEGIN IMMEDIATE` の中で比べ、違えば 409「他の端末が先に変更しました」 | 判断事項（共有 DB を直接読み書きするので、消える変更を無くす） |
| 2 | 同時の新規登録で同じ管理番号が 2 行できうる | 採番と INSERT を同じトランザクションで行い、管理番号に UNIQUE 索引 | 同上 |
| 3 | UPDATE の値を `'値'` で SQL に直書き（エスケープなし） | プレースホルダ | SQL の壊れ方を無くす。結果は同じ |
| 4 | 1 ページ行数 = ListView の高さ ÷ 17.5 | 画面で 12/24/50/100/500 を選ぶ（既定 24） | 画面の高さに縛られない |
| 5 | MF2 の編集欄は 12 個まで（13 列以上の表は直せない） | 列数に上限なし | 制限を残す理由が無い |
| 6 | MF2 で `[` `]` を含む値をクォートで包む（バグ） | 包まない | 再現すると壊れる |
| 7 | `GetNewNo` は 管理番号 の無い表で落ちる | 1 列目を使う | 落とさない |
| 8 | 出力は OS の保存ダイアログ | 設定「出力先」フォルダに保存し、パスを表示 | ブラウザからサーバ側のダイアログは出せない |
| 9 | xlsx 出力・帳票で文字列を書き Excel が数値に解釈 | 数値に見える値は数値セルで書く | 見た目・合計は同じ。再加工しやすい |
| 10 | 帳票の印刷は Excel 既定（A4 縦・縮小なし。13 列は 2 枚に分かれる） | HTML 印刷は横をページ幅（余白 6mm 内側）に収める縮小。xlsx 側は原紙どおり | HTML は列を紙に分けられない |
| 11 | ログインは Excel を閉じるまで有効 | プロセスの寿命（同じ）。加えて設定「無操作で再ログイン(分)」を任意で | 判断事項 D7 |
| 12 | ログアウトなし | 「ログアウト」ボタン | 別 ID で入り直せる |
| 13 | 他 PC の更新は次に一覧を作り直すまで見えない | 心拍で本体の更新時刻を見て「他の端末で更新されました」帯 | 判断事項 |
| 14 | 設定はレジストリと固定パス（`プログラム番号チェック`） | 設定タブ（JSON）。既定値は VBA の固定パスと同じ | 判断事項 |
| 15 | 文字色設定の JS 式を htmlfile の JScript で評価 | ブラウザの `new Function` で評価 | 判断事項 D5 |
| 16 | 参照形式の PDF 等を ShellExecute | サーバ（= この PC）で `os.startfile`、ICON は画像として配信 | 同じ PC で動くので同等 |
| 17 | VER はブック名の `(yyyymmdd)` | `config/app.json` の version | ブック名が無い |

### 表を持ってくる（python-web-tools からの移植）での違い

| 元 | DBビューア | 理由 |
|---|---|---|
| Access の変換に accdb_converter（pyodbc / access_parser） | bridge（cscript → ADODB → ACE）で .sqlite3 にしてから読む | 配布先 PC に Python の追加部品を入れられない |
| 関門は管理者パスワード | Level 5 でログイン | DBビューアの権限は ID 表の Level |
| 入れ替えない表: 発注・受払・実績など | メインテーブル・H_ 履歴・ID・控えの表 | Web 版がふだん書き込む表 |
| PalletMaster の在庫の行を残す | 無し | 梱包資材マスタ専用の処理 |
| 消える列の警告は「取り込みで読む列」 | 「設定（`_設定` の項目名・フィルタ）で使っている列」 | 消えると起動時の整合性検査で止まる |

## 3. VBA の癖をそのまま残したもの

- フィルタ WHERE の `mk`（一度 `'` になると以降の値も `'`）。
- 空タイプのフィルタで値に "-" を含むか日付でなければ文字列比較。
- 削除後はフィルタを解除して一覧を作り直す。
- 修正で変更が無ければキャンセル。ダブルクリックで権限不足なら参照に降格。
- txt/csv の行末に区切り文字が残る。
- 帳票 REPORT: Ⅰ列が空のデータ行があると「小計」扱いになる（実データでは起きない）。
- MF2 の削除は全列一致で対象を引き直す。
- ID を OS のログイン ID から変えると「使用中のIDはPC使用者と一致しません」。
- 起動モード未設定なら先にオンライン/オフラインを選ばせる（regUF）。初期化の文言も同じ。
