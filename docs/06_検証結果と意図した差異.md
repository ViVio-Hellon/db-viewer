### 照合で分かったデータ側の事実（是正は運用側）
- 帳票の「更新者」「更新日」列は VBA 出力例と値が違う。原因は列の付け替え（#19: 現在の `登録者` 列に出力例の「更新者」の値が入っている）で、Web 版は列名のまま扱う。
- `RA` `PC化` `完了` の `?` は DB の値そのもの。
- 作業名の半角カナ/全角カナは VBA 出力例と DB で表記が違う行がある（#20 と同種）。比較は `StrConv(vbNarrow)` 相当を通して行った。

## 2. 意図した差異（VBA と違えたところ）

### 表を持ってくる（python-web-tools からの移植）での違い

| 元 | DBビューア | 理由 |
|---|---|---|
| Access の変換に accdb_converter（pyodbc / access_parser） | bridge（cscript → ADODB → ACE）で .sqlite3 にしてから読む | 配布先 PC に Python の追加部品を入れられない |
| 関門は管理者パスワード | Level 5 でログイン | DBビューアの権限は ID 表の Level |
| 入れ替えない表: 発注・受払・実績など | メインテーブル・H_ 履歴・ID・控えの表 | Web 版がふだん書き込む表 |
| PalletMaster の在庫の行を残す | 無し | 梱包資材マスタ専用の処理 |
| 消える列の警告は「取り込みで読む列」 | 「設定（`_設定` の項目名・フィルタ）で使っている列」 | 消えると起動時の整合性検査で止まる |

## 3. VBA の癖をそのまま残したもの

- フィルタ WHERE の `mk`（一度 `'` になると以降の値も `'`）。
- 空タイプのフィルタで値に "-" を含むか日付でなければ文字列比較。
- 削除後はフィルタを解除して一覧を作り直す。
- 修正で変更が無ければキャンセル。ダブルクリックで権限不足なら参照に降格。
- 帳票 REPORT: Ⅰ列が空のデータ行があると「小計」扱いになる（実データでは起きない）。
- MF2 の削除は全列一致で対象を引き直す。
- ID を OS のログイン ID から変えると「使用中のIDはPC使用者と一致しません」。
- 起動モード未設定なら先にオンライン/オフラインを選ばせる（regUF）。初期化の文言も同じ。
