## 追加確認事項への設計方針

### Access（.accdb）→ SQLite（.sqlite3）

#### 変換の手段（ご指定の経路）

- `subprocess` で `cscript.exe //nologo bridge.vbs "accdb" "出力フォルダ"` を起動。VBScript が ADODB.Connection（ACE OLEDB 12.0）で開き、ADOX でテーブルと**クエリ（VIEW）**を列挙、各表を `SELECT *` して ADODB.Stream で UTF-16 TSV に書く。列の型（adInteger/adDate/adCurrency/adBoolean/adLongVarWChar…）も書く。
- Python 側（標準ライブラリ）は TSV とスキーマを読み、sqlite3 の表を作って載せる。設定画面から進捗つき（jobs）で実行、コマンドラインからも実行可能（`python tools/import_accdb.py`）。
- pyodbc / access_parser は使いません。ACE が各ライン PC にある前提はご記載のとおりです。

#### 型・SQL 方言の差の吸収

- 日付/時刻型 → TEXT。VBA が書く形 `YYYY/MM/DD hh:mm:ss` と一覧・フィルタの比較（`#Y/M/D#`）をそのまま成立させるため、**'YYYY/MM/DD' 形式の文字列に統一**する案を推奨（判断事項 D3）。ISO に変えると既存の文字列列と混在します。
- Yes/No → INTEGER 0/1（表示は VBA と同じ True/False 文字列）。通貨/倍精度 → REAL。オートナンバー → INTEGER（主キーにはしない。VBA も主キーなし運用）。長いテキスト → TEXT。添付/OLE は対象外として記録。
- `FORMAT(x,'#,##0')` は SQL では使わず Python で整形（SQLite の printf の桁区切りは版依存）。`LEFT JOIN` の入れ子括弧は不要。`LIKE` は同じ。`IIf`/`IsNumeric` を含む Access クエリは自動変換しない（不明点 5）。
- テーブル名・列名の `[ ]` 引用は SQLite でも通るため、CODESQL の出力は最小差分で再現できます。テストでは VBA の SQL 文字列と Python の SQL 文字列を並べて比較します。

#### Access 特有の処理

- ADOX によるテーブル作成（`fldAccdb`、Excel→accdb）: デバッグ用のため移植せず、代わりに accdb_bridge。
- クエリ（Q_）を LEFT JOIN 先に使う設定: 取り込み時に「スナップショット表」として写すか、SQLite の VIEW を手で用意するかを不明点 5 で確認。
- `RecordCount=-1` や `E_FAIL`（日付列の 0000-00-00）などの ADO 固有エラーは消えます。
- Access 側の「主キーなし・重複なしインデックス」運用（PPTX 12 枚目）は sqlite3 に UNIQUE 索引として写します。

#### 共有フォルダ上の SQLite 運用の妥当性

SQLite 公式は「ネットワークファイルシステム上での共有はロックの実装次第で壊れうる」と警告しています。Windows の SMB（Windows Server / 一般的な NAS）では byte-range lock が働くため実運用例は多く、python-web-tools も同じ形（取り込み元・書き戻し先が共有の sqlite3）で稼働中です。VBA が Access を共有で直接開いていた運用よりリスクは増えません。条件は次の 4 つです。

- WAL を使わない（共有メモリが置けない）。`journal_mode=DELETE`、`synchronous=FULL`。
- 書き込みは 1 行単位の短いトランザクション、`busy_timeout=10s` + 再試行 3 回。
- 読み取りは手元スナップショット（source_db の方式）で共有上のロックを数ミリ秒しか持たない。
- 同時書込は数台規模を想定。台数が増えて待ちが目立つ場合は、1 台の Flask をサーバー役にして他 PC がブラウザで繋ぐ構成に移れます（設計上、DB 層の差し替えで済むように分離しておきます）。

### 複数 PC・書き込み競合・読み取り中の書き込み

| 場面 | VBA の実態 | Web 版の方針 |
|---|---|---|
| 2 台が同じ行を修正 | 後勝ち（UPDATE を管理番号だけで実行）。片方の変更が黙って消える | 画面が開いたときの値（seen）を送り、サーバーが `BEGIN IMMEDIATE` の中で現在値と比較。違えば 409 で「他の端末が先に変更しました」と最新値を返す。同じときだけ UPDATE + 履歴追記を確定 |
| 2 台が同時に新規登録 | GetNewNo が同じ欠番を返しうる → 同じ管理番号が 2 行できる（重複なし索引があれば片方が ADO エラー） | 採番と INSERT を同じ `BEGIN IMMEDIATE` の中で行う（ロックを取ってから欠番を探す）。管理番号に UNIQUE 索引を付け、万一の重複は 409 で再採番を促す |
| 削除と修正が交差 | 削除済みを UPDATE → 影響 0 行で「更新しました」と出る | 影響行数 0 なら 409「その行はもうありません」 |
| 読んでいる最中に別 PC が書く | ADO のクライアントカーソルで読み切るまで待つ／途中結果 | 読む鍵を取ってからファイルを写すので、常に確定済みの一貫した姿を読む。写しは mtime/サイズが変わったときだけ更新 |
| database is locked | ADO エラーで End | sqlite_toolkit の再試行（1s×回数）。それでも駄目なら 422「他の端末が書き込み中です。少し待ってもう一度」 |
| マスタ（設定テーブル）が他 PC で変わった | 次の起動まで反映されない（MF2 を閉じたときは再初期化） | 設定テーブルは要求ごとに読む（スナップショットの mtime キャッシュ）。列構成が変わっていれば一覧に警告を出し、起動整合性チェックをその場で再実行 |

### 長時間放置・セッション・バックグラウンド・多重タブ

| 確認事項 | 方針（python-web-tools の実装を確認済み） |
|---|---|
| DB 接続を保持し続けないか | 接続は要求ごとに開いて `teardown_appcontext` で閉じる。バックグラウンドスレッドが接続を持つのは accdb 取り込みの最中だけ。ファイルハンドル・ロックは要求の終了で必ず解放 |
| 古いデータを保持しないか | 画面は状態を持たず、一覧・レコードは操作のたびにサーバーから取り直す。`/api/health`（15 秒ごと）に共有 DB の更新時刻を載せ、開いている一覧より新しければ画面上部に「他の端末で更新されました 再読込」を出す。復帰時（`comeBack`）は即座に確認 |
| セッション切れ | 起動トークンはプロセスの寿命と同じ（VBA も Excel を開いている間ログイン状態）。全タブを閉じて 90 秒（閉じた合図なら 8 秒）でプロセスが終了し、次回起動で再ログイン。放置中に別の人が同じ PC を使う想定があれば「無操作 N 分で再ログイン」を設定タブに置けます（既定 OFF、判断事項 D7） |
| ブラウザ放置後の再操作 | レコード画面は開いたときの値を持っているので、保存時に 409 になれば「最新を読み直す」ボタンで再取得。トークンが切れていれば 401 の案内で開き直す |
| メモリ・ハンドル・ロック | プロセス常駐は Flask のみ。スナップショットは temp に 1 つ、古いものは起動時に掃除（`sweep_old_copies`）。ログは日替わりファイル |
| 日付変更後 | #NEWDATE#/#UPDATE#、GetNewCode、カレンダーの「今日」はすべて要求時のサーバー時刻。ログファイルは書く直前に日付を見て切り替え |
| バックグラウンド移行の合図 | `health.js`: `visibilitychange`（裏）で `{visible:false}` を `sendBeacon`、`freeze` でも同じ。サーバー `idle_exit.hidden()` はその画面を「心拍が止まっても生きている」扱いにする |
| 非アクティブ中の自動終了・空き判定の抑制 | `IdleWatch.overdue()`: 裏に回っている画面が 1 つでもあれば終了しない。処理中（`busy()`）も終了しない。1 度も繋がっていなければ終了しない |
| フォアグラウンド復帰・スリープ復帰の検知 | 画面側: `visibilitychange`(表)・`focus`・`pageshow`・`resume`・`online`、およびタイマー間隔が `max(3×心拍, 120秒)` を超えたとき → `{resumed:true, gap_ms}`。サーバー側: 見張りの壁時計間隔が 30 秒超空けばスリープ復帰とみなし 90 秒待ち直す。復帰時は接続確認と一覧の更新確認を即実行 |
| 心拍が止まっても停止しない | 上記のとおり、裏に回った合図を受けた画面は心拍が途切れても数え続ける。閉じたときは `pagehide` の `leaving` が別に届くので、それで落とせる（順不同でも打ち消さない設計） |
| ブラウザタブの多重起動 | db-viewer は作業状態をプロセスに持たないため、タブは独立して動く（画面ロックは採用しない）。心拍は画面 ID ごとに数えるので、1 枚閉じても他が生きていれば終了しない。同じレコードを 2 タブで開いた場合は 409 の競合検知が守る |

### 設定タブ（パスを画面から設定できるように）

#### 面「接続先」

- 接続モード: オンライン / オフライン（VBA のレジストリ値に相当）
- オンライン時の DB フォルダ（UNC）・DB ファイル名、オフライン時の DB フォルダ（既定: アプリのフォルダ）
- 「参照…」はサーバー側フォルダ一覧（fs_browse）。相対パスはアプリのフォルダ基準で、実際の行き先を表示
- 保存すると即座に「見つかったか・sqlite3 として開けたか・必須テーブルが揃っているか・整合性チェック結果」を表示
- 変更には管理者パスワード（Level 4 以上）を要求

#### 面「参照・出力・帳票」

- 参照ファイルの基準フォルダ（相対参照の起点。既定は DB フォルダ）
- 出力先フォルダ（xlsx/txt/csv。既定はアプリのフォルダ下 export）
- 帳票原紙フォルダ（全般設定「帳票」のパスが空欄のときの既定）
- Access.log の置き場所（既定は DB フォルダ、VBA 互換）

#### 面「動作」

- システムプロファイル（progNo 相当: 名前・表示名・既定パス）
- 一覧の 1 ページ行数（既定 30）
- 無操作再ログイン（分、0 で無効）
- 印刷の余白 mm（下限 6mm。文字・罫線・バーが紙端から 5mm 以上内側になるよう `SAFE_MARGIN_MM` でクランプ）

#### 面「Access 取り込み」「いまの状態」「この端末」

- .accdb を選んで sqlite3 に変換（進捗つき）。変換前に既存 sqlite3 のバックアップ
- いまの状態: DB 到達性、必須テーブル、CheckColumns/MasterFileCheck/formatCheck の結果、ID 表の自分の登録と Level
- この端末: ログイン ID・PC 名・Python・アプリの場所・ログの場所・版

### 印刷

帳票・一覧印刷・テーブル印刷は python-web-tools の `printing.py` で作ります。`@page { size: A4 landscape; margin: 6mm }` を下限として文字・罫線・バーコード相当の要素がすべて紙端から 6mm 以上内側に置かれ、画面プレビューも紙と同寸で余白の境界を点線で示します。ブラウザの印刷ダイアログで余白「なし」を選んでも CSS の余白が効きます。

## 移植方針・提案ディレクトリ・工程・検証計画

### 方針の要点

- **配置**: リポジトリ `db-viewer`（現在空）に、python-web-tools と同じ基盤ファイルを複製して独立アプリとして作る。複製元のコミット（d478462, VER3.5.8）を `FOUNDATION_ORIGIN.md` に記録し、基盤の改修を後から同期できるようにする。梱包資材総合ツールのリポジトリには手を入れない。
- **設計規約**: python-web-tools の docs/設計.md を踏襲。業務判断はすべて Python、API は画面ぜんぶを返す、断りは reason 定数、色は tokens.css、同じ事実を 2 か所に持たない。
- **エンジンは設定駆動のまま**: VBA と同様、全般設定・_設定・フィルタ・タイプ・ID の中身だけで画面が決まる。progNo は「システムプロファイル」として設定から選ぶ。
- **Python 側は標準ライブラリ + Flask + waitress**のみ。xlsx 出力は同梱の標準ライブラリ writer、Access 読み取りは cscript 経由。
- **VBA の癖も再現**: フィルタ候補の並び、"-" を含む値の文字列扱い、削除時のフィルタ解除、修正なしのキャンセル、レベルの境界、確認メッセージの文言、txt/csv の行末区切り文字など。直したくなる点はコード中に「VBA どおり」と注記して残す。

### 工程（実装は確認後に着手）

1. **基盤複製と起動確認**（Phase 0）: 起動・待機画面・多重起動防止・心拍・停止・設定画面の骨格が空の業務画面で動くことを確認。`FOUNDATION_ORIGIN.md`。
2. **Access 取り込み**（Phase 1）: accdb_bridge（VBScript + importer）、型対応表、テーブル・クエリの扱い、UNIQUE 索引。実 DB がある場合はここでスナップショットを作り、以降のテスト基準にする。
3. **設定テーブルと整合性**（Phase 2）: settings_tables / schema_check / config。設定タブ「いまの状態」に VBA と同じ判定結果。
4. **一覧・フィルタ・集計・ページ**（Phase 3）: sql_builder / filters / records の読み側。VBA の SQL 文字列と一致するゴールデンテスト。
5. **ログイン・レベル・レコード編集・登録・履歴**（Phase 4）: auth / input_types / numbering / history / records の書き側。補助入力（マスタ・カレンダー・数値・フォルダ・フィールド）。競合検知。
6. **マスタ管理・閲覧・出力**（Phase 5）: master_admin / table_browse / export。
7. **帳票・印刷**（Phase 6）: reports 登録簿と REPORT、印刷用 HTML（6mm）。原紙が届いてから紙面合わせ。
8. **運用機能**（Phase 7）: 更新あり通知、無操作再ログイン（任意）、Access.log、配布手順書。
9. **検証と VBA 比較**（Phase 8）: 実データで VBA と Python の結果を突き合わせ、差分は一件ずつ理由を記録。
10. **完了報告**: docs と変更履歴を整え、未対応・意図的な差異を一覧にして報告。

### 検証計画（VBA と同じ入力 → 同じ結果）

| 対象 | 比較方法 | 期待値の出どころ |
|---|---|---|
| 一覧 SQL（CODESQL）とフィルタ WHERE（GetSQLFilterStr） | 同じ _設定・フィルタ・選択値から生成した SQL 文字列を比較（方言差だけを許容表で吸収） | VBA に「検証ダンプ」マクロを追加し `CODEStr` と `MF1.SQL` を書き出す（私が用意） |
| フィルタ候補の並び・幅 | NonDuplist の並び、YYYY/YYYYMM 変換、比較型の降順、GetWidthArr の px | 同上のダンプ |
| 採番（GetNewNo / GetNewCode） | 既存番号の集合を与えて結果を比較。欠番・当日 0 件・現行コード再利用の境界 | 表計算で作った既知の集合 + VBA 実行結果 |
| 登録の判定 | 必須未入力、修正なし、数値変換（全角・非数値・空）、日付制限（今日ちょうど）、自動項目（新規/修正）、レベル×操作の 5×4 表 | VBA のメッセージ文言と結果を表にする |
| 履歴 | カンマ集合差（追加/削除）、10 列の値、H_ が無いときの無効化 | VBA で数件登録した H_ の行 |
| 出力ファイル | 同じ一覧を xlsx/txt/csv にして比較（行末区切り文字、ヘッダー、結合列） | VBA の OUTPUT 結果ファイル |
