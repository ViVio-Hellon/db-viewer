# デスクトップ版(Tauri / Rust)

0.6.0 から、ブラウザで開く代わりに**専用の窓(exe)**で動かせるようになりました。**ポートを使いません。**
ブラウザ版(`Start.vbs` / `start.bat`)もそのまま残してあり、予備として使えます。
作りは python-web-tools(梱包資材総合ツール VER4.8.14)のデスクトップ版と同じです。

## 1. 何が何をするか(各言語が得意なことをする)

```
DBビューア.exe(Rust / Tauri)                 … src-tauri/
 ├─ 窓(WebView2)・帳票と印刷の窓・終了の確認・多重起動の防止
 ├─ ブラウザ版が動いていたら、理由を窓で出して止まる
 ├─ Python を子として起動・監視(見つからない・落ちたら理由の画面)
 └─ 画面の要求(app://…)を受けて、Python の標準入力へ渡す
        │ 標準入出力(1件 = 見出し1行 + 本文)
        ▼
bridge.py(Python)                             … ポート無しの入口
 └─ Flask アプリを WSGI として呼ぶだけ(待ち受けない)
        ▼
app/・dbviewer/(Python)                       … 業務(VBA と同じ判定・SQL・採番・履歴・帳票)・画面の組み立て(変わらず)
app/static/js(JS)                             … 画面の操作(変わらず。窓まわりだけ desktop.js・確かめの窓は askbox.js)
dbviewer/accdb_bridge/bridge.vbs(VBScript)    … Access(.accdb)を読む(cscript → ADODB → ACE。変わらず)
scripts/make_shortcuts.vbs(VBScript)          … 配った先でショートカットを作る(Windows の機能だけ)
```

| 担当 | 理由 |
|---|---|
| **Rust**: 窓・起動・終了・多重起動・同時起動の断り・Python の監視 | OS の窓とプロセスとファイルの錠を扱うのが得意。exe 1つで配れる |
| **Python**: 業務の判定・SQL・採番・履歴・帳票・画面 | VBA と同じ結果を守る試験(実データの帳票 0 差など)がこの形で書かれている。重い計算は無く(一覧 327 件で数十 ms)、書き直す利点が無く危険だけがある |
| **JS**: 画面の操作 | 今までどおり。デスクトップ版のときだけ、別窓・外のサイト・印刷の「閉じる」を外枠に頼む |
| **VBScript**: Access を読む・ショートカット | 配る先の PC にある Windows の部品(ACE・WSH)だけで動く。Python に追加の部品を入れられない制約に合う |

## 2. 事前確認: 今の機能をデスクトップ版で保てるか(2026-10-10)

移行の前に、画面・API・裏の処理を 1 つずつ「ブラウザに頼っているところ」が無いか調べた結果です。
**保てないものはありませんでした。** 直す必要があったものは「直した」に書いてあります。

| 機能 | ブラウザ版の作り | デスクトップ版でどう保つか | 結果 |
|---|---|---|---|
| 画面ぜんぶ(ログイン・一覧・登録・マスタ管理・閲覧/出力・設定) | Flask が waitress で待ち受け | Flask を WSGI として呼ぶ(`bridge.py`)。画面・API は同じもの | 保てる(試験で確認) |
| 起動トークン・Host の確認・別のページからの要求の断り | 127.0.0.1 の待ち受けを守る | 外枠が毎回トークンを付けて渡す。宛先 `app.localhost` を足しただけ | 保てる(試験で確認) |
| 一覧のその場で直す・登録・マスタの列と行の追加・競合の確認 | API | 同じ API | 保てる(試験で確認) |
| 長い処理(Access の変換)と進み具合 | 背景スレッド + `/api/jobs` | 同じ。要求は 8 本まで同時に捌く | 保てる(試験で確認) |
| 心拍・他の端末の更新の帯・無操作の再ログイン | `/api/health` | 同じ | 保てる |
| タブを閉じたら自動で終わる | 心拍が途絶えたら終わる | 窓の × / 「終了」で終わる(心拍の自動終了は使わない) | 置き換え |
| 「終了」の確認(実行中の処理) | `/api/shutdown` が 409 | 窓の × も同じ確認を通る | 保てる |
| **確かめの窓(9 か所: 削除・上書き・表の入れ替え・起動モード初期化・終了など)** | ブラウザの `confirm()` | Tauri の窓では `confirm()` が**出ないまま進む**(python-web-tools で起きた)。画面の中の窓(`askbox.js`)に置き換えた | **直した** |
| **帳票・印刷の画面** | `window.open` の新しいタブ・Ctrl+P | 外枠が別の窓を開く(`desktop.js`)。画面に「印刷する」「閉じる」ボタンを付けた(窓にはメニューもタブの × も無い) | **直した** |
| 参照ファイル(PDF など)を開く・フォルダを開く | Python が `os.startfile` | 同じ(同じ PC で動く) | 保てる |
| ICON の画像 | Python が返す | 同じ | 保てる |
| 表を持ってくるのドラッグ&ドロップ | 画面で受けて送る | 外枠がドロップを横取りしない設定。本文は 512MB まで | 保てる(実機で要確認) |
| 表をコピー(クリップボード) | `navigator.clipboard` | WebView2 でも同じ | 保てる(実機で要確認) |
| ファイルに保存(CSV・xlsx) | 設定のフォルダへ Python が書く(ダウンロードしない) | 同じ | 保てる |
| 記録番号・操作の記録・画面のエラーの送信 | `X-Request-Id`・`/api/log/client` | 見出しはそのまま外枠を通る | 保てる(試験で確認) |
| Access.log | Python | 同じ | 保てる |
| stop.bat | ブラウザ版を止める | デスクトップ版は止めない(窓で閉じる)。動いていればそう言う | 置き換え |
| 要る Python の部品 | Flask・waitress | デスクトップ版は Flask だけ(waitress はブラウザ版用) | 減る |
| ポート | 8790 など(0.36.0 までは 8743) | 0 個(試験と exe の確認で確かめる) | なくなる |

あわせて、python-web-tools で起きた「**数を勝手に丸めて書く**」が無いかも調べ、2 か所を直しました(0.5.1。CHANGELOG)。

## 3. ブラウザ版とデスクトップ版は同時に動かない

同じ本体(.sqlite3)・設定・記録に 2 つの Python が書きに行かないよう、**後から開いたほうが止まります。**

| 先に動いている | 後から開いた | 動き |
|---|---|---|
| デスクトップ版 | ブラウザ版(Start.vbs) | ブラウザに「起動できませんでした / デスクトップ版がもう動いています」と次にすることを出して止まる |
| ブラウザ版 | デスクトップ版(exe) | 窓(メッセージ)で「ブラウザ版がもう動いています」と次にすることを出し、「閉じる」で終わる |
| ブラウザ版 | ブラウザ版 | 今までどおり、動いているほうの画面を開く |
| デスクトップ版 | デスクトップ版 | 新しく起動せず、開いている窓を前に出す |

仕組み: どちらの版も、業務を始める前に OS のファイルロック `%LOCALAPPDATA%\DBViewer\runtime\app.lock` を取り、
終わるまで握ります(`launch_guard.hold_app_lock`)。取れなければもう一方が動いています。プロセスが落ちれば OS が外すので、
錠が残って起動できなくなることはありません。誰が握っているかは `app_owner.json` に書きます(止まる側の文に使う)。

## 4. 動きの約束

| 場面 | 動き |
|---|---|
| 起動 | 窓がすぐ出て「起動しています」→ 待機画面 → ログイン |
| 窓の × / 画面の「終了」 | 実行中の処理(Access の変換)があれば訊く(ブラウザ版の「終了」と同じ確認) |
| 帳票・印刷 | 別の窓で開く。「印刷する」で印刷の窓、「閉じる」でその窓だけ閉じる |
| アプリの外のページへのリンク | 既定のブラウザで開く(アプリの窓では開かない) |
| Python が見つからない・起動できない | 理由と次にすること(Python の入れ方・pip の打ち方)・ログの場所を窓に出す |
| Python が途中で落ちた | 窓を読み直して理由の画面を出す |
| exe を止めた | 標準入力が閉じるので Python も終わる(取り残さない) |

Python は**同梱しません**。各 PC に入っている Python を使います(`python.exe` → `py.exe -3` の順に探す。
`DBVIEWER_PYTHON` で指定もできる)。デスクトップ版に要るパッケージは Flask だけです。

## 5. 作り方と配り方

**Windows 版は GitHub Actions が作ります**(`.github/workflows/desktop-windows.yml`)。push のたびに、
Python の試験・Rust の試験・exe の作成・exe を起動しての確認まで流れ、成果物 `DBViewer-windows` に `DBViewer.exe` が入ります。

配るとき:

0. (同じ設定で始めさせたいとき)設定 →「**配布設定**」で書き出す(0.30.0。下の「配布設定」)
1. 成果物から `DBViewer.exe` を取ってきて、ツールのフォルダの**直下**(`Start.vbs` と同じ場所)に置く
2. `scripts\make_dist.bat` をダブルクリックする
3. ツールの隣に `DBビューア_VER版` ができる。中に `DBビューア.exe` が入っている。**このフォルダを各 PC に配る**
4. 配った先の PC で `scripts\make_shortcuts.vbs` をダブルクリックすると、ツールのフォルダ(`scripts` の1つ上)に次の2つができる:
   - `DBビューア(ブラウザ版).lnk` … `Start.vbs` を指す
   - `DBビューア(デスクトップ版).lnk` … `DBビューア.exe` を指す(アイコンも exe のもの)
   - 指す先は**押したときのフォルダの場所**。何度押しても作り直すだけ。フォルダを移したら、もう一度押す
   - exe が入っていないフォルダでは、デスクトップ版のショートカットは作らず、そのことを結果の窓で知らせる
   - Windows の機能(WSH)だけで動く。Python や追加のライブラリは要らない

### 配布設定(0.30.0。python-web-tools と同じ作り)

1 台で決めた設定を、配った先の PC でそのまま使います。設定 →「配布設定」で、入れる項目を選んで
**管理者パスワード**を入れて「配布設定を書き出す」を押すと、ツールのフォルダの直下に `配布設定\` ができます。
`make_dist.bat` はこのフォルダも配布フォルダに入れます(入れたくないときは `make_dist.py --no-settings`)。

| 入れられるもの | 中身 |
|---|---|
| 設定ファイルの場所 | 権限・かんたん設定・接続先の .sqlite3(共有フォルダに置いていれば、これだけで全員が同じものを見る) |
| 設定ファイルの中身 | 上のファイルの 3 つの表を `設定ファイル.json` にしたもの。**この PC の中に置いているとき**に入れる |
| 開く DB・参照・出力・記録の置き場所・Access.log・再ログイン | その PC の設定(`user_config.json`) |
| Access 取り込みの元・保存先 | 既定では入れない(取り込むのは管理する PC だけのことが多い) |
| 管理者パスワード | 撹拌した値のまま入れる(平文は入らない。画面・はじめに読む.txt には「(設定済み)」とだけ出す) |

**配った先の決まり**: 起動したときに読み込みます。**その PC で変えた設定は上書きしません**
(無い項目・空の項目だけ埋める)。設定ファイルは、その PC の設定ファイルがまだ無ければ中身で作ります。
書き出し直した配布設定なら、前の配布のまま変えていない項目は新しい値に入れ替えます。揃えたいときは
設定 →「配布設定」→「読み込み直す」(管理者パスワード)。共有フォルダの設定ファイルは読み込み直しでも上書きしません。
この PC の中を指す場所(`C:\Users\…` など)を書き出すと、「配った先に同じ場所が無いと使えません」と知らせます。
`配布設定\` はリポジトリには入れません(`.gitignore`)。

手元で作るとき(開発機):

```
cd src-tauri
cargo test --release
cargo build --release            # target/release/DBViewer(.exe)
python ../scripts/desktop_smoke.py --exe target/release/DBViewer    # Linux は xvfb-run を前に付ける
```

Linux で作るには WebKitGTK が要ります(`libwebkit2gtk-4.1-dev` など)。

## 6. 置き場所の決まり

- exe は `bridge.py` と同じフォルダに置く(上の階層もたどるので、`src-tauri/target/...` から動かしても見つかる)。`DBVIEWER_ROOT` で指定もできる
- 版は `config/app.json`・`src-tauri/tauri.conf.json`・`src-tauri/Cargo.toml` の 3 か所。食い違うと試験が落ちる
- アイコンは `scripts/make_desktop_icon.py` で作る(`src-tauri/icons/`。画面の帯と同じ色の「DB」)

## 7. 確かめきれていないこと(Windows の実機で見る)

この版の確認は Linux(WebKitGTK)の上で窓を実際に動かして行いました。Windows では GitHub Actions が
「起動して画面が届く・待ち受けない・2つ目は起動しない・ブラウザ版は止まる・止めたら Python も終わる」まで確かめます。
次は**実機で人が見る**必要があります:

- 窓の × で、Access の変換中に確認が出ること
- 帳票の「印刷する」から実際に紙が出ること(WebView2 の印刷の窓)
- 「表を持ってくる」のドラッグ&ドロップ、「表をコピー」の貼り付け
- ファイルの列のプレビュー(0.10.0)で、PDF が WebView2 の窓の中に表示されること
- ブラウザ版が動いているときに exe を開くと、理由の窓が出て「閉じる」で終わること
- `scripts\make_shortcuts.vbs` で 2 つのショートカットができ、デスクトップ版のアイコンが exe のものになること
